# Резервне копіювання та відновлення

GitHub зберігає історію, але не замінює незалежну резервну копію. Відповідальна особа повинна мати доступ до GitHub і Cloudflare через персональний обліковий запис із 2FA; спільні паролі не використовуються.

## Що копіювати

- весь приватний Git-репозиторій разом з історією;
- `src/content/`, `public/media/` і `public/files/` як окремий контентний архів;
- `.pages.yml`, конфігурації Astro та документацію;
- експорт або скриншоти налаштувань Cloudflare Pages, environment variables без значень секретів і Access policies;
- перелік уповноважених редакторів та дата останньої перевірки доступів.

## Графік

- автоматично: GitHub зберігає кожен CMS commit;
- щотижня: дзеркальна локальна копія Git-репозиторію на захищеному носії;
- щомісяця: архів контенту й медіа, зашифрований і збережений окремо від робочого комп'ютера;
- перед зміною домену, структури колекцій або масовим імпортом: ручна контрольна копія.

Не зберігайте токени GitHub/Cloudflare у репозиторії чи незашифрованому архіві.

## Перевірка копії

Щонайменше щокварталу відновити копію в тимчасовий каталог і виконати:

```sh
npm ci
npm run audit:repo
npm run verify
```

Перевірка вважається успішною, якщо збірка проходить, PDF та зображення присутні, а неопубліковані матеріали не з'являються у `dist/`.

## Відновлення

1. Зупинити редагування в Pages CMS і зафіксувати останній справний commit.
2. Створити нову гілку від справного commit або відновити файли з перевіреного архіву.
3. Запустити `npm run verify`.
4. Переглянути diff; не переписувати історію `main` без окремого погодження.
5. Злити виправлення через pull request і перевірити Cloudflare preview.
6. Після production deployment перевірити ключові сторінки, PDF, RSS, sitemap і статуси контенту.

Якщо витік токена вже стався, видалення його з останнього commit недостатньо: токен треба негайно відкликати в сервісі, створити новий і провести перевірку журналів доступу.
