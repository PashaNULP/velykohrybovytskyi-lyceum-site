# Контент і майбутня інтеграція Pages CMS

## Статуси

- `draft` — чернетка;
- `review` — матеріал очікує перевірки;
- `published` — матеріал можна показувати на сайті.

Сайт запитує лише записи зі статусом `published`. Для `draft` і `review` не створюються сторінки; вони не потрапляють до списків, RSS та sitemap.

Це не є механізмом конфіденційності. Вміст Markdown і завантажені файли доступні людям, які мають доступ до репозиторію, а в публічному репозиторії — всім. Не додавайте персональні або чутливі матеріали до отримання дозволу.

## Відповідність полів

| Astro / frontmatter | Pages CMS | Призначення |
| --- | --- | --- |
| `body` | `rich-text`, Markdown | Основний текст |
| `publishedAt`, `documentDate`, `date`, `expiresAt` | `date` | Дати у форматі `yyyy-MM-dd` |
| `category`, `status` | `select` | Значення з контрольованого списку |
| `cover.src` | `image` | Головне зображення |
| `gallery[]`, `photos[]` | повторюваний `object` | Фото, alt-текст і підпис |
| `pdf` | `file`, лише PDF | Документ у `public/files` |
| `slug` | `string` з pattern | Стабільна адреса сторінки |

## Іменування

- Markdown-файли: `YYYY-MM-DD-korotka-nazva.md`.
- `slug`: малі латинські літери, цифри та дефіси.
- Зображення й PDF: латиниця, без пробілів; Pages CMS застосовує `rename: safe`.
- Опублікований slug не слід змінювати без перенаправлення зі старої адреси.

## Зображення

Тимчасові Google-фото отримують адаптивний `srcset` із ширинами 480, 800 і 1280 px. Для майбутніх завантажень `.pages.yml` використовує `public/media/images`. Перед публікацією потрібні змістовні alt-тексти й перевірка дозволу на використання фотографій дітей.

## PDF

Zod-схема перевіряє формат шляху та фізичне існування PDF у `public/files`. Якщо Markdown посилається на відсутній файл, `npm run build` завершується помилкою з поясненням.

Поточні файли у `public/files/demo` є технічними прикладами й не мають офіційної сили.

## Завершення актуальності оголошень

Оголошення з минулою `expiresAt` відкидаються під час статичної збірки. Щоб оголошення зникло точно в потрібний день, сайт треба перебудувати після цієї дати; пізніше це можна автоматизувати плановою збіркою.
