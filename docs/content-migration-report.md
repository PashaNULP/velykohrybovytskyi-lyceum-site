## Pages CMS і помилка 413

[Конфігурація Pages CMS](https://pagescms.org/docs/configuration/), [поле `file`](https://pagescms.org/docs/configuration/fields/file/) і [налаштування media](https://pagescms.org/docs/configuration/media/) описують роботу з файлами у GitHub, але не декларують гарантований максимальний розмір завантаження hosted-версії. Під час аудиту були виявлені офіційні файли орієнтовно 23 МБ, 52 МБ і 86 МБ. Помилка HTTP 413 означає, що тіло запиту перевищило ліміт одного з проміжних сервісів; висновок про Pages CMS є технічним припущенням на основі поведінки, а не опублікованим лімітом сервісу.

Прийняте рішення:

1. Невеликі PDF зберігати в `public/files` і завантажувати через Pages CMS.
2. Великі офіційні файли залишати в офіційному Google Drive та вказувати `externalUrl`.
3. Зберігати `sourceUrl` окремо, щоб редактор і відвідувач могли перевірити сторінку-першоджерело.
4. За можливості оптимізувати скановані PDF або поділяти дуже великі збірники, не погіршуючи читабельність і юридичну цілісність документа.

## Що не опубліковано

- матеріали без підтвердженої дати або реквізитів;
- застарілий план протидії булінгу як нібито чинний документ;
- фотографії без достатнього контексту чи підтвердження походження;
- персональні списки, внутрішні матеріали та інші дані, не призначені для відкритого доступу;
- дописи Facebook, які неможливо було перевірити через офіційне дзеркало або доступний локальний матеріал.

## Рекомендації редактору

- кожен новий запис має містити `sourceUrl` на офіційне першоджерело;
- перед `published` перевіряти дату, імена, реквізити документа, alt-тексти та дозвіл на фото;
- `featured` застосовувати лише для матеріалів, які мають отримати пріоритет на головній;
- для тимчасового оголошення завжди заповнювати `expiresAt`;
- великі PDF не дублювати в Git без потреби — використовувати офіційне зовнішнє посилання;
- після кожної редакторської зміни дочекатися успішної збірки та перевірити сторінку на телефоні.

## Перевірки

Для приймання змін виконуються:

```bash
npm run audit:repo
npm run verify
npm run test:editorial
```

Окремо перевіряються головна сторінка, каталог документів, архів оголошень і адаптивне меню в локальному Chrome.
